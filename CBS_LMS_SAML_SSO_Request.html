3. LMS login/role logic (for reference)

Valid AD user, existing LMS account    -> logs in, keeps current LMS role
Valid AD user, no existing LMS account -> rejected ("Invalid username or password")

This mirrors the same model already used for ERP: the username is created in the target application (LMS) first, using the same username as AD/miniOrange, and only a user that already exists there is allowed to log in. LMS does not create new accounts on its own from an AD login alone — the sysadmin creates the LMS account (Employee ID = AD username) ahead of the employee's first SSO attempt.

AD/miniOrange remains the only party that checks the password; LMS only checks that the username already exists in its own records.
